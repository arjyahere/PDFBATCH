# Audit TODO

Findings from the repo-wide audit (2026-11-20). Ordered by severity. Unchecked = not fixed.

## Critical — security

- [ ] **Download path traversal** — `app/routers/download_router.py:53-56`. Double-unquoted filename is joined to `output/` with no containment check; `../` can read any file. Fix: resolve with `os.path.realpath` and reject anything outside `realpath(dest)`; also guard `os.listdir(dest)` when the folder is missing.
- [ ] **Upload filename traversal** — `app/routers/process_router.py:35`, `app/routers/misc_router.py:20`. Client filename goes straight into `os.path.join`. Fix: use `os.path.basename()` and generate a unique server-side name; validate extension.
- [ ] **Temp file leak in `/misc/load-columns`** — `app/routers/misc_router.py:20-39`. `os.remove` is skipped when parsing raises. Fix: `finally` block.
- [ ] **CORS allows every origin with credentials** — `app/api.py:28-34`. `allow_origins=["*"]` + `allow_credentials=True` is invalid and ignores `SECURITY__ALLOWED_ORIGINS`. Fix: use the configured allowlist.
- [ ] **No authentication** — `SecuritySettings.api_key_enabled` / `api_key` are never enforced. Fix: add middleware or a dependency for write/admin endpoints.
- [ ] **Internal errors echoed to clients** — `app/api.py:65-68` returns `str(exc)` in the 500 body. Fix: return a generic message; log the detail server-side.
- [ ] **File errors leak server paths and use the wrong status** — `app/core/exception_handlers.py:50-76`, `app/core/exceptions.py:22-60`. The JSON response includes `exc.file_path`, and `FileException` always returns 500, so a missing file looks like a crash and probing `/download/../../...` reveals internal paths. Fix: drop the `file` field from responses; return 404 for not-found.
- [ ] **Flutter web build ships the secrets file** — `flutter_frontend/pubspec.yaml` declares `- .env` as an asset and `lib/main.dart:20` loads it at runtime; the local `.env` has non-empty `API_KEY` and `API_SECRET`. Anyone can fetch `/assets/.env` from a deployed web build. Fix: never bundle secrets as a web asset — leave them empty for web and issue a short-lived token from the backend, or remove the fields. **Unverified on a real Flutter build (Flutter not installed here).**

## Critical — correctness under load

- [ ] **Pause/resume does not work** — `app/services/queue_worker.py:72-81`, `app/services/job_queue.py:226-246`, `app/routers/process_router.py:211-258`. Pause sets `job.status` but the worker checks `ProcessingState.paused`, which is never set; resume re-runs the whole job from file 1. Fix: use one source of truth, check it inside the file loop, and persist progress for true resume.
- [ ] **Cancel is ignored** — `app/routers/process_router.py:261-284`. Worker never checks `JobStatus.CANCELLED`. Fix: abort the loop on cancel.
- [ ] **Multi-worker deployment is broken** — `main.py:45`, `app/config/settings.py:96`, `app/services/job_queue.py:455-465`. 8 Uvicorn workers each get a separate in-memory queue and state; progress/pause/download land on a random process. Fix: default workers to 1 unless Redis is configured and enabled, or move queue+state to shared storage.
- [ ] **Blocking CPU work in async worker** — `app/services/queue_worker.py:301-320`. PyMuPDF/python-docx calls block the event loop, so polling and control endpoints cannot respond during a batch. Fix: `asyncio.to_thread(...)` for the highlight calls.
- [ ] **DOCX pause check can freeze the server** — `app/services/docx_highlighter.py:47-50`. `while processing_state["paused"]: time.sleep(0.2)` runs on the event-loop thread; if that flag is ever set, no request can clear it. Fix: remove the busy-wait and use the job's pause state checked in the worker loop.
- [ ] **Cross-job global state contamination** — `app/services/queue_worker.py:243-252`, `app/services/single_column_engine.py:163`, `app/services/docx_highlighter.py:134,227`. Every job overwrites global `processing_state`; one job's completion can stop another's page loop, and DOCX jobs may write to another job's output folder. Fix: pass job state explicitly through the engines and stop writing the global.
- [ ] **Job state and logs grow forever** — `app/services/queue_worker.py:185-187`, `app/core/state.py:75-94`. Completed jobs stay in `_job_states` and the queue's `_jobs` dict by design; only failures are cleaned up, and every log is kept in memory. After 10,000 jobs, RAM and `/api/v1/process` keep growing. Fix: evict state and job records after a fixed retention window or on DELETE.

## High — wrong results

- [ ] **Progress screen always reports zero matches** — `flutter_frontend/lib/screens/progress_screen.dart:643-654`. A match is counted only if `Note` contains `highlight`/`match`/`exact match`, but every engine writes `Note: "Method 1"`/`"Method 2"`/`"Method 3"` (`single_column_engine.py:291,333`, `multi_column_engine.py:710,789,880,943,1077`, `docx_highlighter.py:166,204`). The logs screen counts them correctly, so the two screens disagree. Fix: count by presence of `Matched Value`/`Matched Pair`.
- [ ] **`clean_memory.bat` wipes data without confirmation** — `Scripts/clean_memory.bat:15-34` deletes everything in `input/` and `output/` with no prompt, and the script is missing from the README script table. Fix: add a Yes/No gate and document it with a warning.
- [ ] **Two-column missing-values report is always wrong** — `app/services/queue_worker.py:347-348`. Tuples are compared against a set of strings, so every pair is reported missing. Fix: compare matched pairs, not raw values.
- [ ] **Column key mismatch** — engines emit `"Column"` (single) vs `"Columns"` (multi); CSV header at `app/services/queue_worker.py:29` uses `"Columns"` and `flutter_frontend/lib/screens/logs_screen.dart:420` reads `"Column"`. Fix: standardise on one key everywhere.
- [ ] **DOCX outputs are never offered for download** — `app/services/docx_highlighter.py:223` names files with `job_id[:8]`, but `app/services/queue_worker.py:359` matches the full job id. Every `.docx` result is missing from `current_job_pdfs`. Fix: use the full job id in output filenames.
- [ ] **Every progress poll ships thousands of logs** — `app/routers/progress_router.py:100-109`, `app/services/queue_worker.py:325-326`. `/progress/logs` defaults to 5,000 entries while the UI polls repeatedly; a 10,000-match job sends megabytes each time. Fix: small default page size plus a cursor or count.
- [ ] **Column matching rescans every row for each candidate pair** — `app/services/multi_column_engine.py:357,379-394`. Nested loops over column combinations, rows, words and values; 10 candidate x-positions make ~45 pairs, each scanning the whole page. Fix: group words by x-position once and sample a fixed number of pages when guessing columns.
- [ ] **Uppercase extensions silently skipped** — `app/services/queue_worker.py:298,311` checks `.pdf` / `.docx` case-sensitively. Fix: `os.path.splitext(...)[1].lower()` and warn on unsupported files.
- [ ] **Temp uploads leak on pause/failure/cancel** — `app/services/queue_worker.py:336-344` cleans up only on full success. Fix: `finally` block in `_process_job`.
- [ ] **Upload size/type limits missing** — `STORAGE__MAX_FILE_SIZE_MB` in `app/config/settings.py:47` is never enforced. Fix: reject oversized uploads in the routers.

## Medium — maintenance and operability

- [ ] **`flutter pub clean` is not a valid Flutter command** — `Scripts/flutter_pub_clean.bat:36`. Flutter has `flutter clean` and `flutter pub cache clean`, not `flutter pub clean`; the script likely fails every time. Line 20 also uses `%ROOT%\flutter` but `ROOT` is never set in that script. Fix: use `flutter clean`, define `ROOT` from `%~dp0..`, and rename the script if cache cleaning was intended. **Unverified — Flutter is not installed here.**
- [ ] **Documented `run_cluster.py` drops query strings** — `batch_highlighter_api_integrated/run_cluster.py:44` builds the upstream URL from `request.path` only. `/api/v1/progress?job_id=abc` is forwarded as `/api/v1/progress`, so job-specific state is lost; line 63 also returns raw exception text in a 502. Fix: append `request.query_string`, or delete this launcher (see next item).
- [ ] **`run_cluster.py` never drains worker output** — `run_cluster.py:117-119` pipes `stdout`/`stderr` but nothing reads them. A chatty worker fills the OS pipe buffer and blocks forever; the restart check at 198-204 never fires because the process is still alive. Fix: redirect to a log file or `DEVNULL`, or read asynchronously.
- [ ] **`run_cluster.py` is a second, unused cluster launcher** — the docs (`Docs/API_DOCUMENTATION.md:328`, `Docs/BACKEND_WORKING.md:951`, `Docs/WORKFLOW.md:199`, backend readme) tell users to run it, but `Scripts/start_cluster.*` launch uvicorn directly. Its port picker at lines 82-90 increments twice and skips every other port. Fix: delete `run_cluster.py` and the doc references; keep one launcher.
- [ ] **Cluster worker defaults disagree** — `Scripts/start_cluster.bat:23` uses 3, `Scripts/start_cluster.sh:29` and `app/config/settings.py:96` use 8. The same repo behaves differently by OS. Fix: one default from settings.
- [ ] **Batch `.env` loader does not skip comments** — `Scripts/start_cluster.bat:14-18` turns comment lines into bogus environment variables; the Bash version at `start_cluster.sh:18-20` handles them. Fix: skip lines starting with `#`.
- [ ] **The safe unhandled-exception handler is dead code** — `app/core/exception_handlers.py:136-175` registers a generic 500 handler, then `app/api.py:65-68` overwrites it with one that returns `str(exc)`. Fix: delete the `api.py` handler so the safe one runs.
- [ ] **Two logging setups and a stray `app/output` folder** — `app/core/config.py:6-28` hardcodes a `RotatingFileHandler` and creates `app/output`, but `.env` sets `STORAGE__BASE_OUTPUT_DIR=output` and `main.py:11` calls `setup_logging()`, which clears those handlers (`logging_config.py:63-64`). One dead handler chain and one unused empty directory. Fix: delete `app/core/config.py` and have the four engines import `get_logger()` from `app/config` instead.
- [ ] **A bare log filename crashes startup** — `app/config/logging_config.py:81` calls `os.makedirs('')` when `LOGGING__FILE_PATH=app.log`. Fix: only create the directory when one is present.
- [ ] **Column dropdowns can show a stale value** — `flutter_frontend/lib/screens/configuration_screen.dart:290-298` passes `initialValue` to `DropdownButtonFormField` instead of `value`, so programmatic changes in `_handleColumn1Selection` (lines 331-348) may not refresh the display. Fix: pass `value:`. **Unverified — needs a real Flutter run.**
- [ ] **Selectors notify listeners on no-op** — `flutter_frontend/lib/providers/highlighter_provider.dart:196-213` calls `notifyListeners()` even when the selection did not change; `_handleColumn1Selection` calls it several times in a row. Fix: return early when the list is unchanged.
- [ ] **Config ignores OS environment variables** — `app/config/settings.py:10-23` reads only `.env`. Fix: fall back to `os.environ`; cache the file read; validate int/float values with clear errors.
- [ ] **Stale version strings** — `app/api.py:22`, `app/api.py:72`, `flutter_frontend/pubspec.yaml:5` say `1.0.0`; repo is `v1.3.2`. Fix: single source of truth.
- [ ] **Unknown error code `FILE_SAVE_FAILED`** — `app/services/multi_column_engine.py:1245` is absent from `app/core/error_codes.py:16-37`. Fix: add the code or use an existing one.
- [ ] **Wrong positional args to `format_error`** — `app/services/single_column_engine.py:120` puts the message in `category` and the exception in `message`. Fix: use keyword arguments.
- [ ] **Dead duplicate worker** — `app/services/worker.py` and `app/services/pdf_highlighter.py:87` (`pdf_highlight_file_legacy`) are still exported but unused, with a divergent CSV schema. Fix: delete them and their exports.
- [ ] **Duplicate page cache definitions** — `app/services/multi_column_engine.py:26,160-174,244-260`. Two copies of `_page_data_cache`, `get_page_data_cached` and `clear_page_cache`; the second silently overwrites the first, and the cache is module-level state shared by all jobs. Fix: delete the first copy and clear the remaining cache per job.
- [ ] **Dead repository and DI layers** — `app/repositories/job_repository.py` and `app/dependencies/service_factory.py` are used only by the dead legacy worker (or not at all); no router calls them. "SQLite" mode actually writes JSON files to `jobs/`. Fix: delete both layers and their `__init__.py` exports.
- [ ] **Unused dependencies** — `dio`, `image_picker`, `url_launcher`, `shared_preferences` (`flutter_frontend/pubspec.yaml`) and `pydantic-settings`, `python-json-logger` (`app/requirements.txt`) have no imports anywhere in the tree. `aiohttp` is imported only by `run_cluster.py:11-12`, so it becomes unused once that file is deleted. Fix: remove them to cut install time and attack surface.
- [ ] **Dead frontend config** — `flutter_frontend/lib/config/app_config.dart:18-30,76-77`: `AppConfig.init()` is never called (`main.dart:20` loads dotenv itself) and `apiKey`/`apiSecret` are never sent with requests. Fix: call `init()` from `main()` and wire credentials into `_safeRequest`, or remove the unused fields.
- [ ] **Download URLs are not encoded** — `flutter_frontend/lib/utils/download_helper_web.dart:19,61`, `download_helper_io.dart:18`. Filenames go raw into the URL path and the browser `download` attribute; spaces or `#`/`?` break downloads, and the web helper does not sanitize the saved name. Fix: `Uri.encodePathComponent` and reuse the IO sanitizer on web.
- [ ] **Deprecated FastAPI lifecycle hooks** — `app/api.py:47-63` uses `@app.on_event`. Fix: migrate to `lifespan`.
- [ ] **No tests** — no Python tests and no `flutter_frontend/test/`, despite pytest/httpx in requirements. Fix: add at least one test per critical path (upload validation, download containment, pause/resume, multi-column report).
- [ ] **No CI or deploy config** — no workflows, Dockerfile, or deployment manifests exist. Fix: add a minimal CI job running the new tests and a Flutter analysis pass.
- [ ] **Stray generated files** — root `preview_backend.html` is an unreferenced documentation preview; `batch_highlighter_api_integrated/Cloudflare` is a tracked 29-byte note ("Tunnel for localhost:8000") with no references. Fix: delete both (or move the preview under `Docs/` if it is intentionally kept).
- [ ] **Docs overpromise** — README and `Docs/TOOL_DOCUMENTATION.md` claim working pause/resume and multi-worker scaling. Fix: update after the behaviour is fixed.
